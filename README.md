# Расчёт заказа товаров у поставщиков

Программа читает список товаров (CSV или JSON) и рассчитывает, сколько единиц каждого товара нужно заказать. Для каждой рекомендации показывает, как получилось число.

Автор: noPlanBonlyA. Код предоставлен только для оценки тестового задания, подробности в [LICENSE](LICENSE).

## Запуск

Нужен Python 3.10 или новее. Сторонние библиотеки не нужны.

```bash
python3 -m reorder examples/products.csv
```

Команды выполняются из корня проекта, где лежит этот README. В Windows вместо `python3` пишите `python`.

Дополнительные параметры:

```bash
python3 -m reorder examples/products.json                 # тот же расчёт по JSON
python3 -m reorder examples/products.csv -o report.csv    # сохранить отчёт (.csv, .json или .txt)
python3 -m reorder examples/products.csv --extra-days 10  # запас на 10 дней сверх срока поставки вместо 7
python3 -m reorder examples/invalid.csv                   # пример сообщений об ошибках во входных данных
```

Тесты:

```bash
python3 -m unittest -v
```

## Как считается заказ

| Величина | Формула |
|---|---|
| Период покрытия | `lead_days + 7` |
| Целевой запас | `⌈daily_sales × период покрытия + safety_stock⌉`, округление вверх |
| Доступно | `stock + incoming` |
| Заказ | `max(0, целевой запас − доступно)` |

Товар в пути (`incoming`) засчитывается как уже имеющийся, потому что по условию он придёт не позже новой партии.

## Входные данные

Колонки: `sku, name, stock, daily_sales, incoming, lead_days, safety_stock`.

- `stock`, `incoming`, `lead_days`, `safety_stock` — целые числа ≥ 0.
- `daily_sales` — число ≥ 0, может быть дробным. Принимается и точка, и запятая (`1.5` или `1,5`).
- `sku` должен быть уникальным, `name` не пустым.
- CSV может быть с разделителем `,` или `;` (так сохраняет русский Excel), BOM в начале файла не мешает.
- JSON — список объектов с теми же полями.

Если в файле есть ошибки, программа выводит их все сразу с номерами строк и завершается с кодом 2. Расчёт по частично некорректным данным не выполняется: лучше не заказать, чем заказать по ошибочной цифре.

## Пример результата

Для [examples/products.csv](examples/products.csv):

```
Обработано товаров: 6. Нужно заказать: 3.

К ЗАКАЗУ
SKU   Товар   Заказ, шт
A001  Coffee         44
A003  Sugar          21
A006  Milk           14
Итого                79

ПОЯСНЕНИЕ РАСЧЁТА

A001 Coffee — заказать 44 шт.
  период покрытия: 5 + 7 = 12 дн.
  целевой запас:   ⌈4 × 12 + 8⌉ = ⌈56⌉ = 56 шт.
  доступно:        12 на складе + 0 в пути = 12 шт.
  заказ:           max(0, 56 − 12) = 44 шт.

A003 Sugar — заказать 21 шт.
  период покрытия: 7 + 7 = 14 дн.
  целевой запас:   ⌈2 × 14 + 6⌉ = ⌈34⌉ = 34 шт.
  доступно:        8 на складе + 5 в пути = 13 шт.
  заказ:           max(0, 34 − 13) = 21 шт.

A006 Milk — заказать 14 шт.
  период покрытия: 1 + 7 = 8 дн.
  целевой запас:   ⌈1.5 × 8 + 2⌉ = ⌈14⌉ = 14 шт.
  доступно:        0 на складе + 0 в пути = 0 шт.
  заказ:           max(0, 14 − 0) = 14 шт.

ЗАКАЗ НЕ НУЖЕН
A002 Tea — целевой запас 43 шт., доступно 70 шт. (50 + 20 в пути)
A004 Cookies — целевой запас 65 шт., доступно 100 шт. (100 + 0 в пути)
A005 Water — продаж нет, целевой запас 0 шт., доступно 0 шт. (0 + 0 в пути)
```

Готовые файлы результата: [examples/output.txt](examples/output.txt) (вывод в консоль) и [examples/report.csv](examples/report.csv) (сохранённый отчёт).

В [examples/products.json](examples/products.json) собраны случаи с дробными продажами, где округление вверх действительно меняет результат: `⌈0.7 × 9 + 1⌉ = ⌈7.3⌉ = 8` и `⌈3.25 × 11 + 4⌉ = ⌈39.75⌉ = 40`. Там же товар, которого ровно хватает (заказ 0), и товар без продаж.

## Структура

```
reorder/
  calc.py      — формула расчёта (единственное место, где она описана)
  loader.py    — чтение CSV/JSON и проверка данных
  report.py    — текстовый отчёт и сохранение в файл
  __main__.py  — командная строка
tests/test_reorder.py — автотесты: формула, граничные случаи, проверка ввода, CLI
examples/             — входные данные и пример результата
```

## Решения, которые стоит пояснить

- **Decimal вместо float.** При float `0.1 × 30` даёт `3.0000000000000004`, и округление вверх превращает это в 4 вместо 3. Для расчёта заказа такая ошибка недопустима, поэтому продажи читаются сразу в `Decimal` (см. тест `test_no_float_error_on_exact_product`).
- **Число дней сверх срока поставки (7) вынесено в константу `EXTRA_DAYS`** и параметр `--extra-days`, так что это условие легко поменять.
- **Формула находится в одной функции `calculate()`** и не зависит от формата ввода и вывода. Изменение условия расчёта затрагивает только `calc.py`.
